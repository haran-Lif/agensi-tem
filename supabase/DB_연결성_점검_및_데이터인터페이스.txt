DB 연결성 점검 및 칼럼별 데이터 인터페이스
작성일: 2026-07-13
대상: OPS 프로젝트 운영 관제 HTML + Supabase public schema

이 문서는 현재 HTML이 읽고 저장하는 DB 테이블 기준으로 작성한 정적 점검 문서입니다.
실제 Supabase 데이터 값의 누락 여부는 DBeaver에서 확인 쿼리를 실행해야 최종 확인할 수 있습니다.


1. 전체 점검 요약

- teams
- positions
- employees
- project_members
- task_history
- output_history
- output_rules
- project_changes
- worker_task_status
- app_profiles

HTML이 직접 저장하는 운영 테이블

- teams
- positions

- project_members

- output_history
- output_rules

계정/권한 전용 저장 경로
- app_profiles / app_user_projects
- 계정 생성/수정은 app_admin_upsert_auth_account RPC를 사용

현재 확인된 연결 구조
- projects.project_id 기준으로 project_members, task_history, output_history, output_rules, project_changes가 연결됩니다.
- projects.parent_project_id는 같은 고객사의 운영·구축 추가/확장 계약을 기준 projects.project_id와 연결합니다.
- employees.employee_id 기준으로 project_members, task_history.owner_employee_id, output_history.owner_employee_id, project_changes.changed_by_employee_id, worker_task_status.employee_id가 연결됩니다.
- teams.team_id 기준으로 employees.team_id, projects.assigned_team_id가 연결됩니다.
- positions.position_id 기준으로 employees.position_id가 연결됩니다.
- task_history.task_id 기준으로 output_history.task_id, worker_task_status.task_id가 연결됩니다.
- output_rules.rule_id 기준으로 output_rules.conversion_target_rule_id가 연결됩니다.
- app_profiles.user_id 기준으로 app_user_projects.user_id, worker_task_status.user_id가 연결됩니다.
- app_user_projects.project_name은 projects.project_name과 이름 기준으로 연결됩니다.

주의 및 수정 완료 사항
- 006_worker_task_access.sql 안의 role check가 예전 권한 목록으로 되어 있어 operator_output_admin을 다시 막을 수 있었습니다.
- 현재 로컬 파일에서는 operator_output_admin을 포함하도록 수정했습니다.
- DBeaver에 이미 006을 적용한 상태라면 009_role_operator_output_admin.sql 또는 수정된 006을 다시 적용해야 합니다.

주의해야 하는 느슨한 연결
- app_user_projects.project_name -> projects.project_name은 FK가 아니라 이름 매칭입니다.
  프로젝트명을 바꾸면 담당 프로젝트 권한도 같은 이름으로 갱신되어야 합니다.
- employees.employee_name -> app_profiles.display_name은 실무자 자기 업무 조회에서 이름 매칭에 사용됩니다.
  로그인 표시명과 직원명이 다르면 worker 전용 작업 조회가 어긋날 수 있습니다.
- output_history.owner_employee_id는 employees.employee_id와 연결 의도는 있지만 현재 005 SQL에서는 FK가 아니라 text 컬럼입니다.
  화면 저장 시 employee_id를 넣지만, 수동 DB 수정 시 존재하지 않는 employee_id가 들어갈 수 있습니다.
- projects.assigned_team_id는 teams.team_id와 연결 의도는 있지만 002 SQL에서는 FK가 아니라 text 컬럼입니다.
  수동 DB 수정 시 존재하지 않는 team_id가 들어갈 수 있습니다.


2. 테이블별 데이터 인터페이스

2-1. projects
목적: 프로젝트 구성, 계약 정보, 프로젝트 필터, 권한 범위의 기준
Primary Key: project_id
HTML 내부 객체: projectConfigs
저장 함수: operationalRows().projects

칼럼
- project_id: TEXT, 필수, 프로젝트 고유 ID. HTML에서 project._id로 관리
- client_name: TEXT, 필수, 고객사
- project_name: TEXT, 필수, 프로젝트 과업명. app_user_projects.project_name과 이름 매칭
- direction: TEXT, 필수, 운영/구축/이커머스 등 방향성
- status: TEXT, 필수, 진행/종료. HTML에서는 closed면 종료, 그 외 진행
- start_date: DATE, 선택, 계약 시작일
- end_date: DATE, 선택, 계약 종료일
- monthly_contract_amount: NUMERIC, 선택, 월 계약금
- total_contract_amount: NUMERIC, 선택, 총 계약금
- planned_people: NUMERIC, 필수 권장, 계약 인원
- management_people: INTEGER, 필수 기본 0, 프로젝트 관리 인원
- parent_project_id: TEXT, 선택, 추가/확장 계약의 기준 프로젝트 ID
- note: TEXT, 선택, 종료 사유 등 메모
- unit_price: NUMERIC, 선택, 월 계약금/계약 인원 기준 1인 월 평단가
- assigned_team_id: TEXT, 선택, teams.team_id와 연결 의도
- sla_days: INTEGER, 선택, 프로젝트 기본 SLA 영업일

연결

3. 연결 누락/불일치 확인용 SQL

3-1. 담당 프로젝트명이 실제 프로젝트에 없는 계정

select
  aup.user_id,
  p.login_id,
  aup.project_name
from public.app_user_projects aup
join public.app_profiles p on p.user_id = aup.user_id
left join public.projects pr on pr.project_name = aup.project_name
where pr.project_id is null;

select conname, pg_get_constraintdef(oid) as definition

where conrelid = 'public.app_profiles'::regclass
  and conname = 'app_profiles_role_check';


4. 권장 보완 사항

권장 1. app_user_projects는 project_name 대신 project_id를 갖는 구조가 더 안전합니다.
- 현재는 프로젝트명 변경 시 권한 매칭이 깨질 수 있습니다.
- 단기적으로는 프로젝트명 변경 시 app_user_projects도 같이 갱신해야 합니다.

권장 2. app_profiles.display_name과 employees.employee_name 이름 매칭은 장기적으로 user_id 또는 employee_id로 연결하는 구조가 더 안전합니다.
- 현재는 이름 변경/동명이인에서 실무자 작업함 매칭이 어긋날 수 있습니다.

권장 3. output_history.owner_employee_id와 projects.assigned_team_id에 FK를 추가하면 수동 DB 오류를 줄일 수 있습니다.
- 다만 이미 잘못된 데이터가 있으면 FK 추가 전에 정리 쿼리가 먼저 필요합니다.

권장 4. 006_worker_task_access.sql을 다시 적용할 일이 있으면 operator_output_admin이 포함된 최신 파일을 사용해야 합니다.
