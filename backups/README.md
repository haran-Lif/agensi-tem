## Git 보관 범위
- 최종 웹 소스, vendor, 테스트, 변경 기록, SQL 및 운영 안내.
- supabase-config.example.js: 새 환경용 연결 예제. 실제 supabase-config.js는 로컬에 유지하고 Git에서 제외.
- 고정 테스트 비밀번호가 들어 있는 수동 계정 설정 SQL 008/010은 보관 대상에서 제외.
- 기존 버전 ZIP, 원본 Excel, 임시 파일, 개인 분석 결과 및 생성된 PDF는 제외.

## 아직 백업하지 않은 데이터
이 폴더의 소스만으로 운영 데이터를 복원할 수 없습니다. 현재 Supabase DB의 프로젝트·팀·인원·배정·산출물 단가·W/D·목표 공수·계정 권한·업무·평가 원장 및 Storage 파일은 별도의 백업 대상입니다.
현재 DB 설정을 추출했다는 의미가 아니며, 로그인 계정·세션·비밀번호를 포함하지 않습니다.

## 복원 순서
1. 저장소 복제 후 정적 웹 서버에 소스 배치.
2. 기존 Supabase를 계속 사용하는 경우 연결 설정 및 적용된 SQL 이력 확인.
3. 새 DB로 복원할 경우 실제 DB 백업과 Auth/Storage 복원 자료 확보. 이 저장소의 SQL은 기존 업무 테이블을 전제로 하는 증분 스크립트를 포함하므로 001부터 일괄 실행만으로 전체 DB가 생성된다고 가정하지 않음.
4. 평가관리 026, 목표 공수/공개 일간 027의 적용 상태 확인.
5. `node --test tests/*.test.cjs` 실행 후 실제 로그인·조회·저장·권한을 검증.
6. 공개 일간은 프로젝트별 공개 설정 및 daily-public.html 확인.
